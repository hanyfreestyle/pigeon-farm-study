# حدود التحويل من المجال إلى النظام

> مرجع للمراحل القادمة لمنع التحويل المباشر من نتائج تحليل المجال إلى تصميم تقني قبل أوانه. هذا الملف لا يغير أي نتيجة سابقة، ولا يستبدل التحذيرات الموجودة في ملفات Phase 1.

## كيان المجال لا يساوي جدول قاعدة بيانات

**كيان المجال (Domain Entity) ≠ جدول قاعدة بيانات (Database Table).**

وجود مفهوم حقيقي في المزرعة لا يعني تلقائيًا أن له جدولًا مستقلًا. يُحسم التمثيل التقني فقط بعد اكتمال تحليل العلاقات وقواعد العمل ومتطلبات النظام.

## حدث المجال لا يساوي حدثًا برمجيًا

**حدث المجال الواقعي (Domain Event) ≠ حدث برمجي (Software Event).**

ملاحظة حدث فعلي مثل وضع بيضة أو فقس أو نفوق أو نقل لا تعني تلقائيًا إنشاء Event Class أو آلية Events تقنية.

## متطلب المعلومات لا يساوي حقل قاعدة بيانات

**متطلب المعلومات (Information Requirement) ≠ حقل قاعدة بيانات (Database Field).**

المعلومة التي يحتاج المربي أو التحليل إلى معرفتها لا تعني تلقائيًا Column مستقلًا. قد تكون مشتقة أو مركبة أو جزءًا من سجل أو علاقة أو مصدر آخر.

## قرار المشروع لا يساوي حقيقة موثقة

**قرار المشروع (Project Decision) ≠ حقيقة موثقة (Verified Fact).**

قد يعتمد صاحب المشروع اتجاهًا تشغيليًا أو نطاقًا أو أولوية دون أن يعني ذلك أن هذا الاتجاه يمثل كل المزارع أو أنه حقيقة عامة عن السوق.

## الحاجة إلى تحقق ميداني لا تعني غياب الاتجاه

**يحتاج تحققًا ميدانيًا (Field Validation Required) ≠ لا يوجد اتجاه (No Direction).**

يمكن أن يكون اتجاه المجال أو المشروع محسومًا بما يكفي للاستمرار، مع بقاء انتشار الممارسة أو قيمها أو تفاصيلها المحلية بحاجة إلى تحقق في المزارع المصرية.

## القيمة المرجعية لا تساوي ثابتًا

**القيمة المرجعية (Benchmark) ≠ ثابت (Constant).**

العمر أو الوزن أو المدة أو النسبة المرجعية قد تعتمد على السلالة أو الموسم أو المسكن أو الإدارة أو السوق أو تعريف القياس، ولا تتحول تلقائيًا إلى قيمة ثابتة داخل النظام.

## حالة المجال لا تساوي Enum برمجيًا

**الحالة التشغيلية في المجال (Domain Status) ≠ تعداد برمجي (Software Enum).**

استخدام وصف تشغيلي مثل نشط أو ضعيف أو جاهز أو قيد الحضانة لا يعني تلقائيًا اعتماد قائمة Enum ثابتة. يتم تحديد الحالات البرمجية لاحقًا بعد تحليل المسارات وقواعد الانتقال.

## قاعدة الاستخدام

في المراحل التالية، عند الانتقال من تحليل المجال إلى تحليل النظام أو التصميم التقني، يجب الرجوع إلى هذا الملف قبل تحويل أي مفهوم أو حدث أو معلومة أو حالة أو قيمة مرجعية إلى تمثيل برمجي.
